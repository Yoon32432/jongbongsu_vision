# 종량제 봉투 인식 파이프라인 — 정확도 정리 (2026-08-21)

## 1. 파이프라인 구조

1차: YOLO(seg) 탐지 → 2차 검증: HSV 색상 시그니처 + depth 볼록도(bulge_height)

- 실외/야간용으로 별도 임계값(`NIGHT_*`)을 씀 (주간용 `SATURATION_MAX=200`과 별개로 `NIGHT_SATURATION_MAX=150` 등).
- **실외에서는 depth 검증이 꺼져 있음** (`scripts/live_demo_night.py`의 `DEPTH_FILTER_ENABLED = False`). 직사광선 아래서 RealSense IR depth가 깨져(2026-08-05 로그: 쓰레받이의 bulge가 봉투보다 큼) 신뢰할 수 없다고 판단, 실외 실배포 판정은 **색상만으로** 이뤄짐.
- 반면 아래 3절의 실측치들은 대부분 `compare_demo.py`로 뽑은 것이고, 이 스크립트는 depth 검증을 끄지 않고 그대로 씀 → 실측 수치와 실제 실외 배포 설정(depth OFF) 사이에 차이가 있다는 점 감안 필요.

현재 라이브(야간/실외) 임계값:
| 항목 | 값 |
|---|---|
| HUE_RANGE | (29, 110) |
| SATURATION_MIN | 40 |
| NIGHT_SATURATION_MAX | 150 |
| NIGHT_VALUE_RANGE | (20, 220) |
| NIGHT_MIN_GREEN_RATIO | 0.3 |
| NMS(iou_threshold) | 0.5 |

## 3. 정확도 실측

### 3-1. Ground truth 라벨 있는 데이터 (최종 임계값, 2026-08-14)

`compare_demo.py` 라이브 화면 녹화를 실제 영상과 대조해 눈으로 정탐/오탐 확인 (거리 유효 프레임만 집계):

| 영상 | 쓰레받이(impostor) 오탐 배제율 | 봉투(genuine) 정탐율 |
|---|---|---|
| 4.mp4 | 88.1% | 97.4% |
| 5.mp4 | 93.9% | 67.9% (한 번 확실한 미탐 있음) |

→ 두 영상이 정반대 방향 오차를 보임: 오탐 배제를 올리면 정탐이 빠지는 트레이드오프가 그대로 보임. 아직 두 지표를 동시에 만족하는 지점을 못 찾은 상태.

참고 베이스라인 (튜닝 전, 08-13): `night_outdoor_rec1.mp4`에서 오탐율 74.8~79.6% → 이후 튜닝으로 크게 개선은 됐음.

### 3-2. 최신 실외 라이브 테스트 (2026-08-19, street1~4.mp4)

사용자 확인: **street 영상들은 음식물쓰레기통을 제외하면 전부 종량제봉투**(genuine). 즉 이 영상들에서 통과율 ≈ 대략적인 정탐율(genuine recall)로 봐도 됨 — 다만 음식물쓰레기통이 오탐지(false detection)로 잡힌 프레임이 섞여 있을 수 있어 정확한 값은 아니고 근사치.

`compare_demo.py`로 실시간 녹화한 4개 영상 (라이브 RealSense 캡처, color+depth 검증 둘 다 ON — 실배포 설정인 depth OFF와는 다름):

| 영상 | 프레임 수 | 통과율(전체) | 통과율(거리 유효 프레임만) |
|---|---|---|---|
| street1 | 5,572 | 69.4% | 67.5% (5,106 프레임) |
| street2 | 5,259 | 72.7% | 70.9% (4,843 프레임) |
| street3 | 4,741 | 74.2% | 72.5% (4,383 프레임) |
| street4 | 1,926 | 85.5% | 84.9% (1,846 프레임) |
| **합계** | **17,498** | **73.5%** | **71.9%** (16,178 프레임) |

→ 3-1의 4.mp4(97.4%)보다는 낮고 5.mp4(67.9%)보다는 높은 중간 수준. 08-14 이후로 정탐율이 크게 무너지진 않은 것으로 보임.

### 3-3. 무더기(pile) 진단 — ⚠️ 수치 불일치, 신뢰도 낮음

같은 street1~4.mp4를 대상으로 봉투 개수별 통과율/축별(H·S·V) 통과율을 별도로 재분석한 로그(`pile_diagnosis_1787140017.csv` / `pile_diagnosis2_1787141521.csv`, 7,536프레임)가 있는데, 여기서 나온 **전체 통과율은 16.2%** — 위 3-2의 73.5%와 크게 다름.

| 탐지 개수 | 통과율(pile_diagnosis) |
|---|---|
| 1개 | 12.5% |
| 2~6개 | 15.8% |
| 7개 이상 | 35.5% |

축별 병목(전체 평균): hue 91%, **saturation 38~43%**, value 62~75%.

**이 수치는 그대로 못 믿음.** 같은 영상인데 3-2(73.5%)와 3-3(16.2%)이 4배 넘게 차이 나는 이유를 못 찾음 — pile_diagnosis를 만든 스크립트가 저장소에 없어서(임시로 짜고 지운 것으로 보임) 정확히 뭘 어떻게 측정했는지 재현이 안 됨. 유력한 원인 추정: pile_diagnosis는 mp4 파일을 직접 읽는데, 이 mp4가 만약 `compare_demo.py`의 화면 녹화본(이미 통과=초록/거부=빨강 오버레이가 픽셀에 합성된 영상)이라면, 그 오버레이 색 자체가 재측정에서 채도/색상 판정을 오염시켰을 수 있음. 확인 전까지 **3-3 수치는 참고용으로만 쓰고 보고서 본문에 확정 수치로 넣지 말 것**. 탐지 개수와 통과율의 관계도 가설(무더기일수록 나쁨)과 반대 방향으로 나와서 더 의심스러움.

## 4. 요약 / 다음 단계

- 확실한 라벨 기반 수치는 3-1(4.mp4 97.4%/5.mp4 67.9%)뿐이고, 3-2(73.5%)는 "거의 다 genuine"이라는 사용자 확인 기반 근사치.
- 위 수치 전부 depth 검증 ON 상태로 측정 — 실배포(`live_demo_night.py`)는 depth 검증이 꺼져 있어(햇빛에 IR 깨짐) 색상만으로 판정함. 실제 배포 조건과는 차이가 있다는 점 명시 필요.
- 3-3 pile 진단 수치는 3-2와 4배 차이 나는 원인 불명 — 재현 스크립트가 없어 검증 불가, 보고서에 확정치로 쓰지 말 것. 필요하면 pile 진단을 다시 돌리되 스크립트를 저장소에 남겨야 함.
- 정확한 정탐/오탐 분리가 필요하면 `video_review.py`로 street1~4.mp4에 g(봉투)/x(음식물쓰레기통) 라벨을 직접 매기는 게 가장 확실함(음식물쓰레기통만 x로 표시하면 되므로 라벨링 자체는 빠르게 끝남).
- 실외 채도 하한(40)이 현재 병목 후보 — 주간 값을 그대로 쓰고 있어 재조정 여지 있음.
